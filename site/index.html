01 / Features

A binder, not a project file

The binder PDF is the document. Save overwrites it; an editable session rides inside the file itself. Nothing to lose, nothing to explain to the next preparer.

Marks that survive

Tick marks, stamps, tapes, shapes and notes export as standard PDF annotations and render in Acrobat, Edge, Chrome and macOS Preview. Every mark's position is pixel-verified in two independent render engines.

Bookmarks that follow pages

Reorder anything; the outline moves with it. Drag a bookmark and its whole section of pages moves. Imported outlines nest and retarget instead of breaking.

Calculator tapes with addends

A ten-key adding machine on the page. Whole-cent arithmetic, never floating point, and a total always carries the entries behind it, so a reviewer sees the work, not just the answer.

Real inputs

PDFs, .xlsx / .csv, .md / .docx, and images. A spreadsheet becomes pages whose cells are real text, so a figure off a trial balance is read exactly rather than OCR'd and guessed.

Scans, read honestly

On-device OCR gives agents eyes on photographed documents, labelled as a machine reading with per-word confidence, never presented as the document's own text. Built in on macOS. On Windows today it needs Tesseract installed alongside, and says so rather than guessing.

One portable file out

Send a copy with the marks printed on permanently for whoever needs it. The working binder, with its editable session, stays yours.

02 / Agents

The agent preps. You review. Same binder.

Not a chat box bolted onto a GUI. It is an MCP server exposing the same model the app drives, so an agent works in the binder you have open, and you watch it happen.

  • An agent reads the actual pages, including embedded text, exact cell values and OCR'd scans, then finds a figure by name and marks it where it sits.
  • It has the whole toolbar, not a subset: ticks, stamps, calculator tapes and notes, plus rectangles, ellipses, arrows, highlights and text boxes. Anything you can draw, it can draw.
  • Its marks are outlined on the page, so a first pass by an agent and your own review read apart at a glance, not only in the comments pane. Every action is attributed to the AI, journalled in order, and revertible in one step.
  • Agent file access is off by default and scoped to folders you name. The tool never decides what an agent may read. You do.
  • Works with Claude and any MCP client, against a live window or headless.

03 / Your data

What this software does, and what it does not do

No claims here about what any of that means for your obligations. The regimes further down are raised because a tax or accounting professional will have to think about them, not because a PDF tool can settle them. Whether this application fits a given standard in your practice is your call, made against your own policies.

What it does

  • Runs entirely on your machine and makes no network calls. No telemetry, no accounts, no cloud, no auto-update.
  • Keeps binders, working copies and recovery files in the engagement folder you chose, not a temp directory or a vendor's storage. Owner-only on macOS and Linux; on Windows they inherit that folder's permissions.
  • Opens your source documents read-only and records a SHA-256 of each, checked again on reopen and around every export.
  • Attributes every agent action to the AI, journals it in order, and reverts it in one step. Agent marks are outlined on the page.
  • Publishes its full source under GPL-3.0, so everything on this page can be checked instead of believed.

What it does not do

  • Encrypt your files, enforce a retention schedule, or guarantee secure erasure.
  • Provide access control, engagement locking, reviewer sign-off, an immutable audit log, or any central administration.
  • Decide what an agent may read. Agent file access stays off until you name folders yourself, and reads outside them are refused.
  • Control what your AI client does with what it reads. That program is separate, and under your control rather than ours.
  • Make any determination about §7216, your WISP, Circular 230, or anything else you answer to. It cannot, and does not try.

The one thing that can leave the machine

Connecting an AI agent. Even then LedgerPDF is not what reaches the network: your MCP client is a separate program under your control, and what it reads goes wherever that program sends it. A locally-run model keeps it all on the machine. A hosted one does not, and that difference is yours to weigh.

IRC §7216 and §6713

To consider: whether anything you do here involves a disclosure or use of return information, and if so what consent that calls for and in what form (Treas. Reg. §301.7216-3).

The facts: the application makes no network calls. Agent file access is off until you name folders yourself, and once you do, an agent can read page text, which on a 1040 includes the SSN.

FTC Safeguards Rule and your WISP

To consider: how a local tool fits the written information security program you maintain, and which controls it supplies against which ones it leaves to you.

The facts: binders, working copies and recovery files sit in the engagement folder you chose, not a temp directory or a vendor's storage, and are owner-only on macOS and Linux. The application does not encrypt files itself, enforce retention, or provide access control or administration. Those stay with your device and your firm.

Circular 230

To consider: how you supervise machine-produced work, and how a reviewer can tell it from your own.

The facts: every agent action is attributed to the AI, journalled in order and revertible in one step, and agent marks are outlined on the page. The tool reaches no conclusions and signs nothing.

AICPA Code of Professional Conduct

To consider: whether connecting an agent brings a model provider into your engagement as a third party for confidentiality purposes, and what consent or agreement you would want in place first.

The facts: with no agent connected there is no vendor account, telemetry endpoint or support tunnel in the software. Connect one and what it reads goes wherever that program sends it.

This list is not complete and is not meant to be. State board rules and breach-notification statutes vary, engagement letters differ, and your firm's own analysis governs all of it. What LedgerPDF can offer is a boundary small enough to check: the source is published under GPL-3.0, so you or your IT reviewer can verify the factual half above against the code rather than take it from us, and DATA-FLOW.md sets out where every file goes. IRS Pubs 4557 and 5708 are useful starting points if your WISP is not written yet.

A note on the security prompts, since this is a tool you are being asked to trust with client files. macOS builds are signed with a Developer ID certificate issued to Ledger Labs LLC, notarized by Apple and stapled, so they open without a Gatekeeper warning.

Windows builds are not signed yet, so Windows may show a SmartScreen warning. It did not appear on our own first install test, on Windows 11 with Defender on and the file marked as downloaded from the internet, but a stricter machine, an enterprise policy or Smart App Control still can. That prompt is worth reading properly. It says Windows does not recognise this file yet, which is a statement about reputation rather than about safety. Signing improves it without removing it, because reputation accrues per certificate over downloads and time. That is why signing ships as an update instead of holding up the release.

What a certificate cannot give you is the rest of it: the full source under GPL-3.0, Windows installers built by CI rather than on someone's laptop, and install instructions that explain the prompt instead of telling you to click past it.
