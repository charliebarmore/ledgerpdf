The tax workpaper binder built for humans and AI agents.

Drag in what you actually have — tax-software PDFs, Excel trial balances, scans, phone photos — and get one ordered, bookmarked binder. Tick it, tape it, tie it out. Or have an agent do the prep while you review, in the same file.

Replaces Acrobat + TicTie Calculate. Firms pay ~$400 per seat, per year, for two tools to do one bounded job — and the add-on requires the other to run. This is that job, in one tool you can read the source of.

A binder, not a project file

The binder PDF is the document. Save overwrites it; an editable session rides inside the file itself. Nothing to lose, nothing to explain to the next preparer.

✓Marks that survive

Tick marks, stamps, tapes, shapes and notes export as standard PDF annotations and render in Acrobat, Edge, Chrome and macOS Preview. Every mark's position is pixel-verified in two independent render engines.

✓Bookmarks that follow pages

Reorder anything; the outline moves with it. Drag a bookmark and its whole section of pages moves. Imported outlines nest and retarget instead of breaking.

✓Calculator tapes with addends

A ten-key adding machine on the page. Whole-cent arithmetic, never floating point, and a total always carries the entries behind it — so a reviewer sees the work, not just the answer.

✓Real inputs

PDFs, .xlsx / .csv, .md / .docx, and images. A spreadsheet becomes pages whose cells are real text — a figure off a trial balance is read exactly, not OCR'd and guessed.

✓Scans, read honestly

On-device OCR gives agents eyes on photographed documents, labelled as a machine reading with per-word confidence — never presented as the document's own text.

✓One portable file out

Send a copy with the marks printed on permanently for whoever needs it — the working binder, with its editable session, stays yours.

The agent preps. You review. Same binder.

Not a chat box bolted onto a GUI — an MCP server exposing the same model the app drives, so an agent works in the binder you have open, and you watch it happen.

  • An agent reads the actual pages — embedded text, exact cell values, OCR'd scans — finds a figure by name, and marks it where it sits.
  • Every agent action is attributed to the AI, journalled in order, and revertible in one step. Automated marks are distinguishable from yours in the exported PDF.
  • Agent file access is off by default and scoped to folders you name. The tool never decides what an agent may read — you do.
  • Works with Claude and any MCP client, against a live window or headless.

Where your data goes: nowhere

The application makes no network calls.

No telemetry, no accounts, no cloud, no auto-update phoning home. Binders and the client documents behind them stay on your machine. Live agent access is a local socket — never a network port — off by default, with a fresh token every launch. And because the source is public, your own IT reviewer can verify every word of this instead of taking ours.

The one honest caveat

If you point an AI agent at a binder, what that agent reads goes wherever that agent runs. With a hosted model, that is a disclosure of client information — in the US, an IRC §7216 decision that is yours to make, and LedgerPDF deliberately does not make it for you. A locally-run model is the honest way to have both.
