- **Engagement durability baseline — ✅ DONE 2026-07-31.** Session writes are flushed + atomically replaced, keep one previous complete recovery generation, and autosave after the first user-chosen location. Dirty open/close is guarded. A corrupt primary reopens from recovery without overwriting either file. Every source is SHA-256 fingerprinted on import, verified/relinked on reopen, and checked before + after export; export itself is temporary → validate → atomic replace and is forbidden from overwriting a source. Focused persistence checks plus engine regression checks cover the failure paths.

The Python parser now receives a scrubbed environment and has time/output bounds. MCP file access is off by default and canonical-path constrained to explicit `WPT_MCP_ROOTS`, including symlink containment.
- **Native packaging baseline — ✅ DONE on macOS arm64 2026-07-31.** PyInstaller produces a self-contained one-folder PDF engine and electron-builder seals it into the desktop app; the destination needs no Python install. - **Windows x64 — first real hardware run. ✅ BUILDS AND RUNS 2026-08-01.** The `Windows x64` job goes green end to end and the packaged app was launched and driven on a physical ThinkPad: it resolved and spawned the frozen `workpaper-engine.exe`, imported a PDF, parsed its bookmarks, and drew existing marks and thumbnails. Five bugs fixed. The one that mattered: **`os.fsync()` on a read-only handle raises `EBADF` on Windows**, which POSIX tolerates — so *every* binder export failed for *every* Windows user, in the shipped app and not just in tests. Three of the other four were never Windows-specific and broke a clean checkout on macOS too: undeclared `numpy` (Anaconda was supplying it), the Electron 43 binary (upstream dropped its `postinstall`; ours now calls `install-electron`), plus `npm.cmd` spawning and asar path separators. `verify:package` now drives a real export through the **frozen** sidecar and asserts the PDF it wrote, so the exact path that broke is covered automatically on every platform — previously packaged builds ignored the export seam entirely and only the venv Python was ever exercised. **Still open on that hardware:** the unsigned installer has not been run, so SmartScreen's actual wording and click count remain unknown (`spike/WINDOWS-CHECKLIST.md` §2).

- **Page text with positions — ✅ DONE 2026-08-04.** The first piece of the AI tie-out layer, and the thing that made the binder addressable in words. A `text` engine command returns each page as readable lines plus every word with a normalized box; `binder_read_page` and `binder_find` put that in front of an agent, and a hit's coordinates go straight into `binder_place_mark` — so "tick the wages figure" is two calls with no coordinate ever typed by a human. Two traps, both caught and covered: pdfium reports character boxes in **raw user space with rotation NOT applied** while its page size **is** rotated, so boxes go through `geometry.user_to_visual` (the exact inverse of the mark mapping, 300/300 round-trips); and a page the user rotated *inside the binder* displays differently from its source, so coordinates are turned by that delta via `rotateVisual`. Verified against the fixtures' own draw coordinates *and* rendered pixels on the hostile geometries. Line order is rebuilt in user space, not display space, or a `/Rotate 90` page reads in vertical stripes. **pypdfium2 is now a shipped runtime dependency** (BSD/Apache — not the AGPL line the licence guard protects). Scanned pages report `has_text: false` rather than looking blank: that is the honest signal that OCR, not this feature, is what they need. **This materially widens the §7216 boundary — page text, including SSNs on a 1040, can now reach a model.** See `app/README.md`.

- **Agent attribution and revert — ✅ DONE 2026-08-04.** The half of "agentic" that makes it defensible in a file review. Everything an agent creates is stamped with the actor and its run; the session carries a journal of every agent action in the reviewer's language; the status bar says "N by AI" on open and the inspector names the placer; and the exported PDF shows `CJB (AI)` so Acrobat cannot present automated work as the reviewer's own signature. `binder_revert_run` removes a run's annotations — **not** a snapshot restore, because rolling back would discard whatever a person did alongside the agent and would store a copy of the record inside itself; the honest cost is that reordering/rotation/deletion survive, and the result names them rather than looking complete. **Session format bumped to 2** so a build predating attribution refuses the file instead of silently dropping the audit trail on its next save. Two bugs caught by looking at artifacts rather than tests: `activeRun` was being written into saved sessions (a file claiming an agent is working in it), and `.counts b` out-specified the AI count's colour — the same specificity trap that once blanked the Export button.
- **Live agent access — ✅ DONE 2026-08-04.** An agent and the person at the keyboard now work on the SAME binder; before this the MCP server kept its own copy and the app's autosave silently overwrote agent work. **MCP stays on stdio** — it already works there — and only the session crosses, over a local socket speaking **two verbs, pull and push**. Unix socket / named pipe, never a TCP port, so there is no network surface even on loopback; socket and token file both 0600; a 32-byte per-launch token must be the first line sent; OFF by default with a status-bar indicator driven by main so it cannot claim "off" while open. The same `mcp-server.cjs` a client already spawns goes live automatically and falls back to standalone otherwise, with `binder_status` naming the mode. Agent changes arrive through the same `apply` a click does, so they are undoable and autosave normally. 9 checks launch the real app and drive the real server as a real MCP client. **An earlier MCP-over-HTTP attempt was built and discarded** — it reached a working `initialize` but the follow-up notification failed 500 with no server-side trace; the socket design is smaller, safer and reuses the ownership seam.
- **OCR for scanned pages — ✅ WORKING, NOT YET SHIPPABLE 2026-08-04.** Closes the gap that made the tie-out layer blind on the documents preparers most want help with. `binder_read_page`/`binder_find` take `ocr:true`; a rasterized copy of fixture_a gives ground truth, and every figure reads correctly at 92.9% average confidence with boxes that land on the ink — so a figure read off a scan can be ticked where it sits, proven end to end. **Two rules held as non-negotiable:** OCR is labelled a machine reading everywhere it surfaces and carries per-word confidence (a misread digit reaching a tie-out is worse than no reading, because it is wrong confidently); and a page that already has text is never OCR'd. **Platform-native first:** macOS Vision is now the preferred backend — on-device, **nothing to bundle, sign or notarize**, every figure at confidence 1.000 in 0.49s against tesseract's 92.9% in ~2-3s — with tesseract kept as the portable fallback and the engine reported alongside every reading. Vision needed real care: it is line-oriented (per-word boxes come from `boundingBoxForRange`) and its coordinates are **bottom-left origin, y up**, the opposite of everything else here, which would put a tick at the mirror image of the figure. Guarded by asserting both engines place the same figure within 0.02 — they agree to 0.0016 — the same independent-implementation logic as the pdfium+poppler viewer conformance. **Still open: Windows.** `Windows.Media.Ocr` is the equivalent but reports **no per-word confidence**, so it cannot honour the confidence rule; either accept and surface that, or ship tesseract on Windows (~15-40 MB plus signing a second native binary). **Bundling is now a Windows-only question — macOS needs nothing shipped.**
- **Spreadsheets as binder pages — ✅ DONE 2026-08-04.** Closes the biggest gap against "bring in the documents I actually have": Excel IS the workpaper format, and until now an `.xlsx` could not enter a binder at all. `.xlsx`/`.xlsm`/`.csv` import like any source, each worksheet becoming pages built in memory at export — the untouched-source invariant holds. **Cells are really drawn with a font, so the ordinary text extraction reads them exactly** — a figure off a trial balance is addressable and tickable with no OCR in the path, proven end to end through the agent. Deliberate trade: we lay the grid out ourselves rather than bundling a 500 MB office suite, so this renders the DATA, not Excel's print layout (no merged-cell art, conditional formatting or charts — print those to PDF first). Courier chosen so column fitting is exact arithmetic rather than a font-metrics table, and figures align as an accountant reads them. **Uncalculated formulas are shown as formulas and warned about** rather than left blank, because a blank where a number belongs is the worst outcome in a workpaper. **One sheet is one page whenever it can still be read** — the largest type that fits everything on a single page is found first, and the page shape is chosen per sheet (a tall register goes portrait, a wide trial balance landscape). Fixing the orientation is what turned a real 86-row register into a full page plus a 13-row orphan. Below ~4.5pt it paginates instead, because two readable pages beat one nobody can read; wide sheets then split onto continuation pages rather than truncating. Caught in build: grouping text lines by box BOTTOM split a row in two whenever a cell had a descender — grouping by box TOP is stable.
- **Drag a bookmark, move its section — ✅ DONE 2026-08-04.** Asked for while dogfooding: reordering a section previously meant selecting its pages in the thumbnail rail. Dragging a bookmark now moves the pages it owns as one block, in one undo step, with nested bookmarks following because their pages are inside the run. Deliberately unlike Acrobat, whose bookmark drag reorders the outline and leaves pages put — in a workpaper a bookmark is a tab divider, and an outline that disagrees with the binder is worse than no drag at all. The span is the same one the "(N pages)" label already describes, so what a preparer reads is what moves. Same pass: the hover controls `⇤ ⇥ ×` became **Out / In / Delete**, and the dropzone stopped saying "PDFs or images" now that spreadsheets import.
- **Memos as binder pages — ✅ DONE 2026-08-04.** `.md`/`.markdown`/`.docx` import like any source. Charlie named the gap describing his own loop: Claude writes an Excel file, a Markdown file, a memo, and only the spreadsheet could get in. **Typeset, not dumped** — raw markdown in a workpaper puts `## Heading` on the page, and a workpaper that looks like source code is not support for anything. reportlab does the layout because prose needs real font metrics to wrap (the sheet renderer dodges that with monospace, right for figures and wrong for a paragraph); Times-Roman at 1-inch margins matches the firm's own document standard so a rendered memo sits beside a Word deliverable. Text is really drawn, so a figure quoted in a memo is addressable and tickable like any other. Every block type — heading, body, bullet, table cell, blockquote, numbered item — carries its own check, because an unhandled construct does not error, it silently vanishes from the page.
- **Sheets an agent can actually use — ✅ DONE 2026-08-04.** Charlie asked whether a rendered trial balance was even scannable by AI. Measured rather than argued: it was not. The page flattens a row to `1001 Cash 7,412.68 5,310.40 4,982.15 7,740.93` — blank cells vanish, so nothing says which figure is a beginning balance and which is an ending one, and on a trial balance that is the entire meaning. Worse, account 1001 was being rendered `1,001`, so an agent searching for it would never find it. **`binder_read_cells` now hands over the parsed grid** — detected header row, column names, every cell including the empties — because "this column is blank for this account" is what a reconciliation runs on. We had that data at parse time and were throwing it away, making the agent recover structure from a picture. Number grouping now follows the workbook's own format, and numeric columns right-align the way an accountant reads them.
- **Review notes and flagging — ✅ DONE 2026-08-04.** The output side of "make sure the binder is true": an agent that finds a problem now has somewhere to put it that a human will see. `binder_add_note` exports a real PDF **Text** annotation — the subtype Acrobat collects into its Comments pane — so a reviewer meets it where they already look and it survives to anyone opening the binder. **`note` is its own mark kind rather than a comment hung off a tick:** a tick means agreed, and putting one on something an agent is questioning tells a reviewer the opposite of what was meant. `binder_set_status` hands agents the page statuses the app already had, so a flag shows in the rail and bookmark tree while a person scrolls; `binder_review_queue` lists everything waiting on a person, in binder order, with the note and who left it. Caught by its own check: `z.string().min(1)` let a whitespace-only note through, creating an annotation that wasted a reviewer's attention and said nothing.
