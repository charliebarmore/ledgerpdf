- **Phase 1 — binder organizer. ✅ FUNCTIONALLY COMPLETE 2026-07-27** (Electron + React + PDF.js over the Phase 0 engine — see `app/README.md`). Import via dialog + drag-drop · thumbnail rail with drag-reorder, multi-select, keyboard · rotate/delete with undo/redo · file-level bookmarks with imported outlines nested and retargeted · stable page IDs · versioned session save/reopen with a format guard · export merged binder that never touches source files. Verified by `npm run verify`: typecheck + **22 model checks ending in a real engine export** + a **7-check GUI smoke test that drives the actual app headlessly** (import → render → export → `qpdf --check`).
  - **Phase 1.5 (done, from dogfooding a real 62-page master tax file):** zoom in the page view (fit-width/fit-page/100%/steps, ⌘± and ⌘-scroll) · auto page counts on leaf bookmarks with a toggle · editable bookmark titles (double-click, revert, keyed to origin so renames survive reordering) · **add/remove/nest your own bookmarks** (the app previously only derived them, so a PDF with no outline got exactly one) · redundant single-source file wrapper suppressed · `.pdf` stripped from file titles · full-title tooltips and a drag-resizable bookmark panel (real titles are long).
  - Polish still deferred, non-blocking: thumbnail windowing for very large binders (62 pages was not reported as slow) · bookmark fallback to nearest surviving page instead of drop-and-hoist · richer empty/error states.
- **Phase 3 — calculator tape. ✅ DONE 2026-07-30.** 10-key adding machine (digits key the line, Enter commits and the running total updates, `-` flips the sign, `⌫` takes back the keystroke then the last line, Esc puts it down), optional caption, drag to position, each line one undo step. **Money sums in whole cents, never floats.** Entries are stored structurally and exported alongside the drawn lines as `/WPT_Data`, so a total always carries its addends — the seam the tie-out layer reads. Card geometry mirrors the engine's `TAPE_*` constants, and the tape's position is pixel-checked in pdfium alongside the marks.
  - Keystroke feel was specced from Charlie directly rather than a TCR screen-share. Worth 10 minutes of watching a TCR member drive TicTie to confirm the `⌫` and sign behavior before design partners see it.
- **Images as pages. ✅ DONE 2026-07-30** (added at Charlie's direction). PNG/JPEG/TIFF/GIF/BMP/WebP import alongside PDFs — a phone photo of a receipt is a workpaper page. Each becomes one **Letter page, auto-oriented**, converted **in memory at export**, so the session still points at the untouched original and the "a PDF exists only at export" invariant holds. JPEG data is embedded **byte-for-byte** as `/DCTDecode` and EXIF rotation rides on the page `/Rotate`, so a sideways phone photo lands upright with no recompression; only PNG/CMYK/progressive/mirrored cases re-encode, and `probe` reports which and why.
  - **Pillow is now a shipped engine dependency**, not just test-harness (`engine/requirements.txt` updated). License is HPND — fine, and the MuPDF/AGPL guard is untouched.
  - **Watch item:** the Letter framing now exists twice — `imageLayout()` in `session.ts` and `_layout()` in `images.py`. If they drift, a mark placed over a receipt exports somewhere else *silently*. `verify:model` compares the two directly; keep that check.
- **Agent access — MCP server. ✅ DONE 2026-07-30** (added at Charlie's direction, outside the original phase plan). `app/src/mcp/` exposes the binder to Claude and any MCP client: import, reorder, bookmark, mark, tape, export. It is a second front door onto the *same* session model and Python engine, not a reimplementation, so the two can't drift. Registered at user scope as `workpaper-binder`. The `.wptsession.json` is the handoff — no live link to a running app window. 28-check harness drives it as a real MCP client through a whole build plus the error paths.
  - **§7216 note.** Page *text* never crosses — the engine probes structure, not content. File names and bookmark titles still carry client names, so pointing an agent at real files remains a disclosure decision. The original 2026-07-30 frictionless/no-boundary choice was superseded by the 2026-07-31 security review: MCP file access is disabled unless `WPT_MCP_ROOTS` explicitly scopes approved engagement folders, with canonical-path/symlink containment. Redaction/handle mapping remains future work.
- **Drawn annotations. ✅ DONE 2026-07-31** (added at Charlie's direction — the fixed tick/cross/stamp palette wasn't enough to mark up a real workpaper). Rectangle, ellipse, line, arrow, highlighter and text note, drag-to-draw with ⇧-constrain, five fixed colors, editable weight/color/note in an inspector. Engine appearance streams in `engine/shapes.py`; geometry is two normalized display-space corners, pixel-checked in pdfium.
  - **Two traps handled, both of which yield INVALID PDFs rather than ugly ones:** a degenerate drag (a flat line has zero height, and a zero-height `/BBox` divides by zero in the viewer's BBox→Rect fit) and stroke overflow (a stroke straddles its path, so an edge-drawn rectangle gets clipped in half). Both are fixed by padding the form box by the stroke width — don't remove it.
  - Toolbar legibility pass alongside: every tool has a name + shortcut in its tooltip, and two emoji that render as empty boxes on macOS (🖩 calculator, 🗩 note) were replaced with CSS-drawn glyphs. **The `Initials` placeholder said "CJB", which reads as a real value** — it looked filled while actually being empty, which is why the initials stamp appeared mysteriously disabled. Now "—".
  - Deliberately not built: freehand pen (awkward without a stylus), and callout leader lines on text notes.
- **Vertical-slice checkpoint — ✅ CLOSED on this machine 2026-07-30.** Import → organize → tick → tape → export → validate now runs end to end: 88 model checks and a 12-check GUI smoke that drives the real app and asserts marks *and* the tape land at the exact coordinates placed, `qpdf --check` clean. **Still outstanding for the formal gate:** verification in all four viewers (Acrobat, Edge, Chrome, macOS Preview) on **both** platforms — pdfium (Chrome/Edge) and PDFKit (Preview) are covered by the spike harness, but Acrobat on real Windows x64 has never been run.
- **Engagement durability baseline — ✅ DONE 2026-07-31.** Session writes are flushed + atomically replaced, keep one previous complete recovery generation, and autosave after the first user-chosen location. Dirty open/close is guarded. A corrupt primary reopens from recovery without overwriting either file. Every source is SHA-256 fingerprinted on import, verified/relinked on reopen, and checked before + after export; export itself is temporary → validate → atomic replace and is forbidden from overwriting a source. Focused persistence checks plus engine regression checks cover the failure paths.
- **Local privilege-boundary hardening — ✅ DONE 2026-07-31.** Every IPC sender is restricted to the registered main frame; navigation, popups, webviews, and browser permissions are denied; arbitrary renderer path registration was replaced by preload extraction from genuine dropped `File` objects; reveal is restricted to save-dialog outputs. The Python parser now receives a scrubbed environment and has time/output bounds. MCP file access is off by default and canonical-path constrained to explicit `WPT_MCP_ROOTS`, including symlink containment.
- **Native packaging baseline — ✅ DONE on macOS arm64 2026-07-31.** PyInstaller produces a self-contained one-folder PDF engine and electron-builder seals it into the desktop app; the destination needs no Python install. A packaged smoke runs the real main-process→engine boundary, verifies PDF.js WASM/cmap assets inside ASAR, and renders a synthetic tax PDF under `file://`; the ad-hoc app passes deep strict `codesign` validation. Release builds fail closed unless explicitly placed in signed-release mode. **Still required before distribution:** real Developer ID signing/notarization, Windows x64 build + Azure Trusted Signing, installer/SmartScreen testing, and Acrobat/Edge verification on that hardware.
